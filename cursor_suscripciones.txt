1. OBJETIVO Y ALCANCE
================================================================================

1.1. Objetivo Principal
    Integrar Mercado Pago como proveedor de pagos para suscripciones recurrentes
    de cuotas mensuales de socios, respetando la arquitectura Clean Architecture
    y manteniendo la flexibilidad para futuras migraciones (AWS Lambda, otros
    proveedores).

1.2. Alcance Funcional
    - Creación de suscripciones recurrentes en Mercado Pago para miembros (socios)
    - Gestión del ciclo de vida de suscripciones (activa, pausada, cancelada)
    - Webhooks para recibir notificaciones de pagos y cambios de estado
    - Registro automático de movimientos en Cuenta Corriente cuando se procesan pagos
    - Sincronización de estados entre Mercado Pago y el sistema interno
    - Manejo de pagos fallidos y reintentos
    - Soporte para múltiples monedas (ARS, USD, EUR) según configuración del equipo

1.3. Alcance Técnico
    - Extensión de la interfaz PaymentProvider existente
    - Implementación de MercadoPagoPaymentProvider siguiendo Clean Architecture
    - Nuevos endpoints para webhooks de Mercado Pago
    - Actualización de modelos de dominio y base de datos
    - Frontend: actualización de componentes para mostrar estado real de suscripciones
    - Configuración mediante variables de entorno

1.4. Fuera de Alcance (V2)
    - Integración con Stripe u otros proveedores (V3)
    - Liquidación automática mensual (futura iteración)

3.2. Flujo de Suscripción Recurrente

    FLUJO 1: Crear Suscripción para un Socio
    -----------------------------------------
    1. Usuario (admin) configura cuota mensual en config_cuota
    2. Admin genera link de suscripción para un member
    3. Frontend llama: POST /api/v1/subscriptions
       {
         "member_id": 123,
         "amount": 1000.00,
         "currency": "ARS",
         "description": "Cuota mensual - [Team Name]"
       }
    4. Backend:
       a. Use Case: CreateSubscriptionUseCase
       b. Llama a PaymentProvider.create_recurring_subscription()
       c. MercadoPagoPaymentProvider:
          - Crea plan en MP (si no existe)
          - Crea suscripción en MP asociada al plan
          - Retorna subscription_id de MP y approval_url
       d. Guarda en DB:
          - payment_links: link_url = approval_url, provider = "mercado_pago"
          - members: subscription_status = "pending", subscription_link = approval_url
          - (Opcional) subscription: mp_subscription_id, status, etc.
    5. Frontend muestra approval_url al usuario
    6. Usuario completa pago en MP
    7. MP envía webhook: payment.created (primer pago)
    8. Backend procesa webhook y crea movimiento en movements

    FLUJO 2: Webhook de Mercado Pago
    ---------------------------------
    1. MP envía POST a /api/v1/webhooks/mercado-pago
    2. Backend valida firma del webhook (X-Signature header)
    3. ProcessWebhookUseCase identifica tipo de evento:
       - payment.created: primer pago exitoso
       - payment.updated: cambio de estado de pago
       - subscription.updated: cambio en suscripción
    4. Para payment.created/updated:
       a. Verifica que el pago pertenece a una suscripción conocida
       b. Si status = "approved":
          - Crea Movement en movements (tipo: "cuota")
          - Actualiza subscription_status del member a "active"
       c. Si status = "rejected":
          - Marca movimiento como "pending" o crea notificación
    5. Para subscription.updated:
       a. Sincroniza status (active, paused, cancelled)
       b. Actualiza next_billing_date si aplica

    FLUJO 3: Pagos Recurrentes Mensuales
    -------------------------------------
    1. MP cobra automáticamente según frecuencia (mensual)
    2. MP envía webhook payment.created para cada cobro
    3. Backend procesa y crea Movement automáticamente
    4. No requiere intervención manual

    CREATE TABLE IF NOT EXISTS subscriptions (

            'pending', 'authorized', 'active', 'paused', 'cancelled', 'suspended'

        start_date TIMESTAMP,
        next_billing_date TIMESTAMP,
        last_payment_date TIMESTAMP,
        last_payment_id VARCHAR(255),  -- ID del último pago en MP
        date_created TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL,
        date_updated TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL,
        UNIQUE(entity_type, entity_id, mp_subscription_id)
    );

12.3. Cambios de Monto
    - Si cambia monto en config_cuota:
      - Opción A: Cancelar suscripciones existentes, crear nuevas
      - Opción B: MP permite actualizar monto (verificar API)
    - Documentar comportamiento esperado

12.4. Monedas Múltiples
    - MP soporta ARS, USD, EUR
    - Validar que moneda del plan coincida con suscripción
    - Manejar conversión si es necesario (futuro)

12.5. Sincronización de Estados
    - Job periódico para sincronizar estados (opcional)
    - O confiar solo en webhooks (recomendado)
    - Endpoint manual para forzar sincronización
