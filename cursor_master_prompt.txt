ARCHITECTURE & TECH STACK (SUMMARY – DO NOT OVERRIDE)
---------------------------------------------------

Back-end:
- Language: Python.
- Framework: FastAPI (async, ASGI).
- Architecture: Clean Architecture / Hexagonal.
  - domain/
  - application/
  - infrastructure/
  - presentation/ (API).
- Database: PostgreSQL via Supabase (as described in specs).
- Auth: decoupled via an AuthProvider interface.
  - Current impl: LocalAuthProvider (JWT, DB users).
  - Future impl: CognitoAuthProvider (AWS Cognito).
- Future deployment: AWS Lambda + API Gateway (serverless), so:
  - Endpoints must be stateless.
  - No local disk persistence beyond /tmp-like behavior.

Front-end:
- React + Vite + Tailwind CSS.
- Layout with sidebar:
  - Home (team overview with name, logo, bio).
  - Finanzas → Socios (main members management module).
  - Panel de socios (legacy, redirects to Finanzas → Socios).
  - Plantel (Players).
  - Asistentes (AI Assistants chat).
  - Prensa (Press Management, future).
  - Configuración (Settings, future).
- Communication: REST JSON with the backend.

Payments:
- Must be abstracted via a PaymentProvider interface.
- V1: simple/manual or mock provider.
- V2: Mercado Pago subscriptions.
- V3: other providers (Stripe, etc.)

---------------------------------------------------
SCOPE OF V1 (PANEL DE SOCIOS + FINANZAS → SOCIOS)
---------------------------------------------------

Use the functional spec file as source of truth. In summary:

- Implement:
  - A login screen, leading into a team dashboard layout with sidebar.
  - Home page showing team information (name, logo, bio from active campaign or team).
  - Team level system (0-6): Teams have a level_id that determines feature access.
    - Level 0: Basic access, cannot create member campaigns.
    - Level 1+: Can create and manage member campaigns.
  - "Finanzas → Socios" module (main members management):
    - Active campaign verification and display.
    - Level-based campaign creation (requires level 1+).
    - Historical campaigns listing.
    - Members list with full details from userprofile (username, first_name, last_name).
    - Member payment evolution (cuotas history per member).
    - Total paid and pending calculations per member.
  - "Panel de socios" (legacy module, redirects to Finanzas → Socios):
    - The "Cuenta Corriente" (current account) view:
      - Movements: ingresos (quotas, sponsors, collectas, individual contributions) and egresos (fees, cashout).
      - Filters by date, type, status, etc.
    - The basic "Dashboard" view:
      - Charts: ingresos vs egresos, active members, evolution in time (mock data if needed).
  - "Create Campaign" screen for setting up member campaigns (Cuota Social Amateur / Socios Coquita):
    - Team identity configuration (name, logo, bio).
    - Campaign configuration (monthly amount, currency, alternative amounts, payment method).
    - Save as draft or publish functionality.
  - Allow configuration of:
    - A monthly fee (amount + currency, default ARS) per team, as reference for member subscriptions.
  - Each member and sponsor has a payment link for recurring subscriptions (mock or simplified in V1).
  - Collectas:
    - Public or invited.
    - Each collecta has its own link and generates individual income movements.
  - Asistentes (AI Assistants):
    - Chat interface with 5 assistants (Guillote, Quela, Pela, Chori, Marta).
    - Individual conversation per assistant.
    - Message history persistence.

Key API Endpoints (V1):
- GET /api/v1/campaigns/check-access - Check team level and campaign creation capability.
- GET /api/v1/campaigns/active - Get active (published) campaign for team.
- GET /api/v1/campaigns/all - Get all campaigns (active and historical) for team.
- GET /api/v1/members/with-details - Get all members with userprofile data.
- GET /api/v1/members/{member_id}/evolution - Get payment evolution for a specific member.
- GET /api/v1/teams/current - Get current user's team information (includes level_id).

Data Model Notes:
- Members are linked to userprofile table via userprofile_id for additional user information.
- Campaigns can be in "draft" or "published" status. Only one published campaign per team is active.
- Movements table tracks all financial transactions, including cuotas (subscription fees).
- Team level_id determines feature access (campaign creation requires level 1+).

Do NOT implement:
- Transfers between teams.
- Purchases from providers.
- Advanced integrations beyond what is specified for V1.
